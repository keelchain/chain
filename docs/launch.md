# Keel launch plan

Decision, 2026-09-24: the chain is its own brand, **Keel**, network
**Keelchain**, native asset `KEEL`, stablecoin `KUSD`, domain
**keelchain.com** (registered at Cloudflare, proxied). It is issued and
tested on its own, exposes an API for third parties, and SafeTheTrade becomes
its first client rather than its owner.

## 1. What changed

- Every crate `stt-*` is `keel-*`; identifiers `stt_*` are `keel_*`; the
  CLI binary is `keel`; env vars `STT_*` are `KEEL_*`; the consensus and
  p2p namespace is `_KEEL_CHAIN`, so a Keel node never talks to an old
  network.
- Tickers: `STT` → `KEEL`, `STTUSD` → `KUSD` in genesis, tokens, docs and the
  SDK vectors (regenerated by `cargo test -p keel-actions`).
- SDK package `@keelchain/sdk`; explorer titled Keel Explorer; the extension is
  **Keel Wallet** (id `keel-wallet@keelchain.com`, version 1.1.1) exposing
  `window.keel`, with `window.stt` kept as an alias so SafeTheTrade's web
  app keeps working until it switches.
- Brand assets in `brand/` (mark, wordmark, favicon, colours); applied to the
  explorer and the extension icons.
- `site/` is keelchain.com: landing page, `wallet/` page and privacy policy.
- `infra/keel/nginx-keelchain.conf` is the origin config behind Cloudflare.
- Verified: Rust workspace builds, tests and clippy clean; SDK 30 tests;
  explorer 16; extension 43.

## 2. Domains and hosting (Cloudflare in front of the sandbox box)

| Host | Serves | Origin |
|---|---|---|
| keelchain.com, www | `site/` (landing, wallet pages, privacy) | the testnet box, nginx |
| testnet.keelchain.com | explorer at `/`, indexer at `/api/`, node RPC at `/rpc/` | same box, loopback services |

Cloudflare steps: A records `keelchain.com` and `testnet` →
the box IP (proxied), `www` CNAME; SSL/TLS mode **Full (strict)**; an
**Origin CA certificate** for `keelchain.com, *.keelchain.com` installed on
the box as `/etc/ssl/keelchain/origin.pem` and `origin.key`. Then the nginx
config goes live and the sandbox chain is restarted as a fresh Keel testnet
(new namespace = new network; chain id 3 stays). mohabmetwally.com/chain is
retired; mohabmetwally.com/stt (the sandbox marketplace) keeps running as
the first client and points at testnet.keelchain.com.

Cloudflare gives the API product its first controls for free: rate-limiting
rules on `/api/` and `/rpc/`, bot protection, caching of block and
transaction reads, and WAF in front of the node.

## 3. API for third parties

What exists: the indexer's read API (about 40 routes: blocks, transactions,
accounts, assets, markets, candles, offers, trades, vaults, governance,
search, WebSocket) and the node RPC (about 30 routes: status, submit actions,
receipts, order book, vault addresses, WebSocket), both JSON, both public,
and `@keelchain/sdk` for encoding and signing actions.

What a third party still needs, in order:

1. **Stable hostnames and versioning.** `testnet.keelchain.com/api/v1` and
   `/rpc/v1` are the contract; document that `/v1` is frozen and additions
   are backwards compatible.
2. **Reference docs.** A docs site at keelchain.com/docs generated from the
   route tables (`crates/keel-rpc`, `crates/keel-indexer/src/api`) and the
   observer/API markdown, with the SDK README and the wallet provider
   contract (`docs/wallet.md`).
3. **Limits and keys.** Anonymous reads rate-limited at Cloudflare; API keys
   for higher limits and for action submission, issued from a small keys
   service (or Cloudflare API Shield) and passed as a bearer, logged per key.
4. **Webhooks.** Subscriptions to account, offer and trade events, fed from
   the indexer's WebSocket stream, with signed deliveries and retries.
5. **Published SDK.** `@keelchain/sdk` on npm under the `keelchain` organisation, plus
   a `keel` CLI release per tag.
6. **Status page and changelog.** Testnet resets and upgrades announced
   before they happen.

## 4. SafeTheTrade as a client

The marketplace already integrates through the SDK and the two HTTP APIs
(`apps/marketplace/src/modules/chain` in the marketplace repo). Becoming a
client means: depend on the published `@keelchain/sdk` instead of a vendored
tarball; point `CHAIN_RPC_URL`, `CHAIN_INDEXER_URL` and `CHAIN_EXPLORER_URL`
at the Keel hosts; use an API key; switch its web app from `window.stt` to
`window.keel` (the alias covers the interval); and drop its custodial chain
keys in favour of user wallets when it is ready. Its custody transition
(`docs/custody-nodes-plan.md` in the marketplace repo) is its own concern and
does not block Keel.

## 5. Identity and governance still to decide

- Legal entity that publishes the wallet, holds the domain and answers
  store reviewers; support and hello mailboxes on keelchain.com.
- GitHub organisation `keelchain` (free) for the repository, npm
  organisation `keel`, store developer accounts under the entity.
- The token: `KEEL` allocation buckets, team grants and the super-admin
  address were open items under the old name and remain open.
- Testnet policy: how often it resets, faucet, and who runs additional
  validators and observers.

## 6. Next steps

1. Cloudflare DNS and origin certificate; GitHub org; commit branch
   `keel`.
2. Deploy: nginx config, `site/`, the explorer build, and the fresh Keel
   testnet from the `keel-*` binaries; retire mohabmetwally.com/chain.
3. Re-run the wallet end-to-end script against the sandbox marketplace
   through testnet.keelchain.com; resubmit Keel Wallet to the stores from
   the Keel developer account with keelchain.com links.
4. Docs site and API keys (section 3, items 2 and 3).
